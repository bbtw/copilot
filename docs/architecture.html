SourceFetchError
Raised by any fetch node on HTTP error or parse failure. Carries source: str and cause: Exception. The graph aborts immediately — synthesis is skipped. The caller must catch this and mint a new fs_req_id to retry.
SynthesisError
Raised by the synthesis node on LLM gateway failure or parse error. Wraps the root cause. All four source results were already written to state at this point, but recovery still requires a full restart.

API Fetch Object Flow

Read this as two moments in the program: first build_graph creates long-lived objects, then LangGraph calls the captured node for each request. The example is customer_profile; the other source nodes use the same shape with different settings.

LangGraph merges this one field into GraphState. Other source nodes follow the same diagram with their own client, identity, user/pass, and token.
Key ownership rule: the API client owns connection details; the identity owns credentials and token cache. Sharing the token-server oauth_client only shares a connection pool to the token endpoint, not the bearer tokens.
Programmer takeaway. A fetch node is an async function that remembers three object references. The source decides what to request and how to parse it. The API client decides where the HTTP request goes. The identity decides which user/pass token is attached. To understand any other source, follow those same three references.
